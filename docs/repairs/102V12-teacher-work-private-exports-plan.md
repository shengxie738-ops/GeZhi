## Frozen wire v1

All JSON success responses use HTTP 200 `{code:200,message:"ok",data:...}`; errors use their HTTP status as code, controlled uppercase message and data=null. Cache-Control=no-store. Request and JSON response envelope cap262144 UTF-8 bytes. UUID identifiers and UTC ISO timestamps. Strict request fields; no caller owner, paths, model, status, arbitrary format or handler.

- POST `/api/teacher/work/tasks/{task_id}/packages`: required Idempotency-Key (existing1–128 Unicode/no-controls), exact six fields `approval_id,input_revision,outline_revision,outline_digest,source_digest,expected_revision`. Both formats always requested. Existing exact key/body replay performs no DML or new build. First call executes within the bounded request lifetime; concurrent replay can observe persisted in-progress state.
- GET `/api/teacher/work/tasks/{task_id}/packages/{version_id}`: immutable historical package status.
- GET `/api/teacher/work/tasks/{task_id}/packages?limit=20&before=<version_id>`: bounded descending version_no list of this task's manual-approved versions. Exact data `task_id,items,next_before,truncated`; limit1–20/default20; same-task cursor required. Exact item `version_id,version_no,run_id,approval_id,created_at,stage,attempt,artifacts`; exact per-format summary `artifact_id,kind,state,download_available`. Both formats in fixed order; no repeated lesson/slides. More older rows means truncated=true and last item UUID as next_before; otherwise null. READY files/hash are actually verified. A safely resolved owned leaf that is absent, or stable regular bytes with a length/hash mismatch, keeps state=READY but has download_available=false; healthy formats/versions and pagination remain available. Unsafe/unavailable roots, namespace identity races, symlinks, hardlinks, nonregular/oversized files or other unresolved observations still fail closed503. GET performs no state mutation. Original unbound/legacy versions are not certified by this list.
- POST `/api/teacher/work/tasks/{task_id}/runs/{run_id}/retry`: exact body `{"expected_attempt":1}`. No independent retry key; `(run_id,target_attempt=2)` is the natural operation identity. Only failed formats, no READY mutation. A recorded second attempt replays current state. Original absolute300-second deadline remains unchanged. New post-expiry operation requires a new creation key/run/version and current approval checks.
- GET `/api/teacher/work/tasks/{task_id}/artifacts/{artifact_id}/download`: authenticated binary attachment, MIME/Content-Length/UTF-8 filename/no-store/nosniff. READY historical bytes are downloadable regardless of current input/source drift; current teacher/owner and immutable binding/bytes/hash still required.

Download validates the requested format's actual bytes again at finalization while preserving all package SQL/approval/owner binding checks. An isolated missing/corrupt peer does not disable a healthy requested format. A bad requested file still returns503 PRIVATE_STORAGE_UNAVAILABLE. Package status/create/retry keep their existing full-package byte checks; the new resilience behavior is confined to list summaries and per-format downloads.

- GET `/api/teacher/work/packages/capabilities`: exact `create,read,retry,download,storage_configured,reasons` (five booleans and string map). Default-off feature flags stay off. False operation keys have reasons; configured storage means an existing safe local root outside static/frontend roots, never proof of per-owner quota or file readiness.

## Architecture and minimum schema

No new tables. Preserve immutable original v2 ORM/contract/DDL/hash. New v3 definitions add only nullable PackageVersion.approval_id, approval/task referenced unique index and composite FK, and exact READY/manual-package CHECKs. A separate explicit additive v2→v3 migration verifies identity, clean connection, exact old ledger/physical structure, session checks and table resolution; refuses partial or unledgered outcomes. DDL is not rollbackable. New v3 completion ledger is written after complete independent physical observation; INSERT/COMMIT uncertainty stays unknown. Legacy null binding is never certified.

Reuse WorkRun identity/attempt/deadline, existing PackageVersion/Artifact and OwnerRunLease fencing. A new narrow SQL adapter shares the caller-owned root; current account→lease→original draft→task→run/artifact lock ordering. Admission commits run/version/two complete10MiB path claims before any filesystem write. Manual package provider/repair calls stay zero, active AI tokens null.

Storage root is operator-configured local private storage, outside backend/app/static and all frontend/public roots. Root/owner FD pinning, O_NOFOLLOW, UUID-only keys,0700 directories,0600 files, one candidate inode per artifact, fsync and exclusive non-overwriting publish. Inventory includes staging and final files; unfamiliar entries, links, dual different-inode copies, wrong namespace, oversized files or incoherent manifests refuse. NonREADY nonnull key reserves10MiB even when FAILED/unknown; READY charges actual bytes. Under owner lock,200MiB ceiling uses SQL claims AND observed disk inventory. Verified stopped execution and exact owned cleanup precede any release/retry. Unknown commit never authorizes deletion.

Builders run normally imported real Office modules in owned terminable subprocesses, with no DB/AI/filesystem writes in children. Parent owns file publication under fresh fence/authority/source checks.30s per build/validation stage;300s original package lifetime, at most two attempts. Children are stopped/joined on all exits. Filesystem last verification and SQL commit have a finite crash/TOCTOU window, addressed by fail-closed persistent claims and explicit fresh-connection reconciliation, not atomicity claims.

An unconfirmed child termination yields no stopped receipt and keeps its path/lease claim. Fresh exact-create/retry reconciliation can recover a matching process-local stopped fence. After both original run deadline and exactly matching lease expiry, a fresh owner lock can revoke the old publisher with CAS; this proves SQL publication fencing, not remote child termination. Partial files and complete nonREADY reservations remain; no expiry deletion. A stopped all-READY run can complete only after source/normalization/deadline/released-lease rechecks, including the final owner flush. Expired runs cannot extend/reset or retry; a new explicit key needs current approval checks. Capacity reserves directory entries (READY1, nonREADY2, new-format2) as well as bytes before admission.
