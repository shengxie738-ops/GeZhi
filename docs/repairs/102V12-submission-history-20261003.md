# GeZhi 提交与历史查询服务进展

本阶段已完成不可变线性提交、本人提交头与历史查询、教师按当前权限范围查询提交的后端服务，并通过限定范围的源码与合成数据验证。提交 HTTP 端点和前端流程尚未接入，生产写入继续保持关闭。

## 已实现的服务

- 提交必须属于当前账户仍有资格访问的发布。学生身份、冻结版本、内容摘要、接收时间及序号由服务端确定，请求不能自行指定这些事实或评分结果
- 首次提交使用发布时预创建的空提交头；后续提交必须准确引用当前父提交。每次接受均追加不可变记录并推进对应提交头，旧内容保持不变；同一父提交的较晚新请求会发生冲突
- 有权提交但预创建提交头缺失时，返回 503 invalid_assessment_state，不自动补建。当前账户、选课关系和发布接收者资格先于这一新提交状态检查，缺失提交头不会绕过当前权限判断
- 相同请求的重试返回原始回执和原始提交结果，不再次推进提交头。后续出现较新提交、截止时间已过或课程班已归档时，原回执仍按当前权限恢复；当前权限失效会拒绝恢复。恢复原提交不要求今天的提交头仍存在
- 内容按原始 UTF-8 文本保存并计算 SHA-256，保留 Unicode、CRLF 和末尾换行。文本与代码均作为静态内容保存，语言标签不启用执行能力；AI 使用声明是自报信息，不自动证明合规或产生评分
- 本人详情和历史不暴露其他学习者身份、私有答案或发布受众信息。历史按提交序号升序返回，并报告一致视图中的当前提交头及查询时间；历史列表不携带正文或 AI 声明
- 教师详情和列表要求当前提交查看权限，且只能查询当前可信学习者范围内的记录。默认列表返回已提交的当前提交头；指定准确学习者后返回其按序号排列的历史。范围外和未知筛选值不会扩大可见范围或透露范围外对象是否存在
- 学习者退课后，本人访问会失效。教师可在自己的当前权限和可信范围仍覆盖该学习者时查看历史；旧发布接收者记录不会恢复学习者的当前访问资格
- 查询结果明确标注 execution_status 为 not_available、assessment_status 为 not_implemented。接受提交不表示已评测、评分或提升掌握程度

## 分页约束

新增 own_history、teacher_heads、teacher_history 三种有限游标类型。游标绑定当前账户、发布、准确学习者筛选与位置；未筛选的教师提交头游标也必须显式绑定空筛选值。

既有六种游标约束保持不变。编码、UTF-8、字段、重复键、未知字段、位置范围和大小上限均严格校验，并固定验证全部九种格式的最大 Unicode 长度。游标只提供不可信分页位置，每次翻页仍重新检查当前权限。

## 尚未开放的能力与验证限制

生产写入安全门保持原样，仍无条件返回 503 write_safety_unproven；教学功能默认开关未改变。本阶段没有启用、部署或迁移数据库，也没有接入提交 HTTP 流程、前端提交编辑器或真实浏览器操作。

顺序提交、父提交冲突、回滚和回执恢复测试只验证普通顺序状态变化。真实 MySQL 的并发首次提交及同父提交竞争、锁顺序、外键与唯一键等待、提交结果不确定时的恢复、迁移和物理约束等验证仍未执行。既有 B1 真实 MySQL 验证要求与 B2 上线前提继续保留。

本阶段不包含自动评测、评分、反馈、代码运行器、评阅分配、修改机会、后台任务或通知。当前完成的是后端源码与合成验证范围，线上写入可用性仍需单独验证和批准。
