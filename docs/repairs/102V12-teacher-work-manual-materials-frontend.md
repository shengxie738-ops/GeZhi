# Teacher Work：手动教案与幻灯片大纲

## 范围

本阶段仅扩展教师私人 Work 的电脑端：手动编辑完整教案与 6–12 页幻灯片结构，保存不可变大纲，重新读取服务端最新版本，以及明确确认已审阅的精确保存版本。

不生成教学正文，不将聊天建议自动转成教案，不自动审批，不生成 PPTX/DOCX；文件能力固定关闭。既有教师私人任务、教学需求和对话入口继续独立运行。没有浏览器／移动端验收、模型／资料正文调用、依赖安装、部署或主分支合并。

## 界面和编辑

- `手动整理` 是独立的轻色 Work 区块，完整表单通过明确的编辑入口展开；折叠不会丢失草稿或正在执行的操作
- 教案支持标题、主题、课程、对象、课时、六类条目、总结、教学阶段和手动引用；阶段分钟总和必须等于任务课时
- 幻灯片支持六种布局、标题、要点／双栏、讲稿备注和来源说明；手动 evidence_refs 始终为空
- 页数必须精确等于已保存任务目标，范围为 6–12；新增、删除和上下移动不会偷偷截断内容
- 保存版本、来源和审阅状态采用可读文字；技术标识和摘要放在可选详情中
- 服务端读取能力关闭时不开放长表单编辑；来源不可用但读取仍允许时，明确告知当前不能保存，内容仅是未持久化的本页草稿

## 状态与安全边界

新的材料 API 与既有核心能力响应分开，采用闭合字段验证、UTF-8 字节限制、UTC 时间、UUID 和小写 SHA256 摘要。请求／响应 envelope 上限为 262144 字节，规范化教案与幻灯片上限为 131072 字节；后端完整任务原草稿的实际紧凑 UTF-8 存储上限另为 65535 字节，含需求、材料、保留内容和操作回执。所有文本以插值或原生表单属性显示，不使用 HTML 渲染或带认证信息的链接。

保存命令含期望 working/input/outline 版本，审批命令只含精确 input/outline 版本与内容／来源摘要。新保存递增三个版本，新审批只递增 working 版本。每次操作均使用幂等标识。

未保存的材料或任务编辑不能审批。未知旧字段可以由服务端保留并继续手动保存已支持的材料，但审阅仍关闭，不把这些字段当作已整理或已丢弃。版本冲突和其他错误保留输入；重新读取先保留草稿，只有明确选择替换才改用服务端快照。同一身份会话内切换任务或暂时离开 Work 的草稿保留在内存中；重新加载页面不会把未保存内容变成持久数据，身份／角色／认证边界不会复用其他账号的草稿。

提交结果不明时，只能明确重试原始精确内容和标识，之后的新编辑仍保留。回放响应中的当前快照与原始操作回执分别处理，旧回执不会冒充最新大纲，已成功的旧审批回执也不会冒充当前仍有效的审批。

材料操作的已知自身版本增量与外部版本发现分别处理。外部读取／回放发现更新后，先阻止任务写入并重新读取真实任务字段；不能将新版本号贴到旧教学需求上。双向版本变化会取消并复位旧任务、资料和材料读取，避免永久 loading。

## 测试维护与审阅修复

根 HTML 门控区域因八个明确材料事件绑定从 3695 增至 4177 字符。现有有限测试的源码预算从 4000 调整为 4500；所有前台／认证谓词断言保留，新绑定另有逐项验证。这是本功能引起的测试维护，非历史失败。

独立审阅指出并以 RED→GREEN 回归修复：

1. 材料采用新版本后，旧任务／资料读取永久 loading
2. 任务改页数后，旧不可变大纲不能重新读取修订
3. 外部新版本号覆盖在旧任务字段上，可能绕过正确的并发检查
4. 来源／输入变化后，同一原始审批回执被错误维持为结果不明
5. 任务写入使材料读取失效后，材料永久 loading
6. 外部已保存新页数大纲在真实任务字段重新读取前被错误拒绝

紧凑界面的追加审阅还发现来源不可用提示与可点击保存按钮不一致。现已同时在状态层与组件关闭该动作，来源能力关闭也会中止正在提交的操作并保留原幂等回放。终止能力错误下的编辑展开声明与实际可见性保持一致，草稿不变。
