# Teacher Work：教师私人文件与版本

## 本阶段范围

在既有轻色、紧凑的电脑端 Work 中增加文件与版本区块，并复用到文件／版本侧栏。导航折叠、手动材料编辑、教学需求和私人对话继续保持既有结构。仅由教师明确点击，把当前已保存、来源有效且已审阅的手动大纲导出为私人 PPTX／DOCX；没有模型正文调用、自动审批、自动下载、部署或主分支操作。

导出能力来自单独的 `/api/teacher/work/packages/capabilities`。旧材料能力的 `files:false` 保持不变；界面明确说明文件能力另行检查。能力未确认或关闭时，不承诺文件已生成、可导出或可下载。内容标为手动、已审阅，固定模板和结构校验不代表真实 Office 可视效果；用户下载后仍需核对版式。

## 创建、状态与恢复

- 新建导出精确绑定 approval_id、input_revision、outline_revision、outline_digest、source_digest 和 expected_revision
- 尚未保存的任务／材料编辑、正在重新读取或读取失败的材料事实、无效审批、任务冲突，以及实际进行中的写操作，均阻止新建导出
- 单次新操作使用新幂等标识。提交结果未知时，仅提供明确重放原始精确请求和原标识的入口；后来编辑不会改写待确认请求
- HTTP 200 的畸形、无法解析或超过 262144 UTF-8 字节上限的响应，仍可能对应已提交的服务端操作，因此归为结果未知；不会自动放开新标识重复创建
- 服务端回执与当前执行次数分开处理：原创建回执保持 attempt 1，即使历史执行后来进入 attempt 2
- 重试命令固定为 `{expected_attempt:1}`，目标为 attempt 2，无重试幂等 key。仅根据服务端 retry_available 和失败格式开放；未知或中断的重试需重新读取精确执行／版本
- 一个格式成功、另一格式失败时，成功格式仍可单独下载。前端不自行重置旧执行、不猜测后端已生成文件
- 状态查询有次数上限、可中止；到达上限后显示暂停并提供明确查询入口，不自动创建或重试

包响应不包含新的任务 working_revision。后端仅在 COMPLETE 提交时递增 working_revision，未完成、失败和普通回放不会因此递增。创建／重试响应、提交结果未知，以及查询观察到 COMPLETE 后，均重新读取任务与材料事实，保留未保存的需求和材料输入；在重新读取结束之前仍维持临时写锁，不推测版本增量。

## 服务端历史与下载

导出历史每次从服务端读取，不从浏览器内存或 localStorage 重建持久版本。列表默认 20 条，按 version_no 降序；更早页使用最后返回版本的 UUID，保留已读取页面，拒绝重复或非更早的后续项。已知不可用的格式在同一任务作用域内保留关闭事实，重新读取首页省略旧版本不代表恢复；只有新的明确可用观察才解除关闭。当前需求、材料或来源发生变化，不使历史包或其下载依赖新的草稿／来源审批。

历史摘要的 download_available=true 必须对应 READY。安全解析的本账户文件缺失或稳定长度／SHA 不一致时，列表保留 READY 并只将该格式标为 download_available=false，其他格式、版本和分页仍可读；不安全根目录、符号链接、身份／路径竞态等仍返回 503 PRIVATE_STORAGE_UNAVAILABLE。这一隔离行为已由原始原生捕获的 missing／corrupt／empty 案例验证。前端对当前列表已知 false 的格式关闭下载并显示不可用，健康同伴保持可下载；列表可用性降级会中止正在下载的旧请求。详细保存元数据不代替下载接口对实际当前文件字节的最终核验。

下载使用 Bearer 请求头，认证信息从不放入 URL。响应流限定为文件声明大小且不超过 10 MiB；检查 Office MIME、Content-Length、安全的 Content-Disposition UTF-8 basename、实际长度和 SHA-256 后才建立 Blob URL。拒绝重定向、畸形文件名、错误 MIME、超限／截短流和摘要不符；取消读取并释放锁。只有当前身份／任务／视图／能力／选中版本代际，以及点击时冻结的文件元数据仍匹配的请求可以触发下载，已拥有的 Blob URL 随后撤销。文本仅插值或原生属性展示，无不可信 HTML。

## 并发与独立审阅

任务保存使用实际 saveFlight 对应的 busy 标记，不依赖可能被编辑器改写的显示状态。包写操作同时阻止任务保存、新建、材料保存／审批、聊天发送和取消；编辑器保持可编辑。所有读取、写入、轮询、下载与最后清理均按请求所有权和当前作用域验证，旧完成不能更新新的任务或清除新下载的忙碌状态。

独立审阅以 RED→GREEN 回归确认并修复：

1. 聊天取消遗漏包写锁
2. 任务编辑恢复旧保存值后掩盖尚未完成的任务写入
3. 中断的失败格式重试永久保留待确认操作，导致后续写入被锁死
4. 创建后的事实刷新失败，把旧错误写入新任务／身份／能力代际
5. 旧下载的 finally 清理覆盖新下载忙碌标记

另外覆盖退出登录后的待确认内容清除、能力认证失败时私人版本清除、所有能力变化的请求隔离、分页保留、部分成功、脏草稿、HTTP 200 结果不明和受控额度拒绝。原生集成发现的 PRIVATE_STORAGE_UNAVAILABLE／PACKAGE_STATE_UNAVAILABLE 503 可发生在已保存执行之后，因此保留精确原请求。其他已验证服务型 503 同样保守处理；MATERIAL_SOURCES_UNAVAILABLE 的明确准入前 409 单独作为确定拒绝，不永久保留旧请求。既有认证门控内容预算保持小于 4500：新增九个精确事件绑定另逐一断言出现一次并排除后，再应用原预算；根门控由 4177 增至 4665 字符。所有前台／认证谓词及未知包绑定检测保留。旧 API 方法清单按六个明确新增方法扩展，未取消旧断言。
