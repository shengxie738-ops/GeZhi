# 教师 Work 普通对话持久化切片

## 当前状态

本次实现 Task4b2A：普通对话的授权仓储命令、严格记录解码和显式调用方事务内的 SQL 行操作。所有返回值仍是未提交候选或授权观察结果，不能据此发送提供商请求、显示已保存成功或认定事务已经提交。

修正前的 79 项有限合成用例已通过。另一个补充用例确认：显式 SQL 写入失败后，即使 Session 和根事务仍报告活动，原绑定也必须拒绝继续使用。现已增加共享、不可逆的 UoW 失败标记；修正后的 80 项限定用例已全部通过，全部设置、调用与清理阶段通过，无跳过或受限操作失败；补充用例的八种写入失败情形及后续操作阻断均完成复验。没有用合成记录或 SQL 编译代替真实数据库验收。

## 实现范围

- 同一事务内建立用户消息、PENDING run 和教师独占 lease；精确键重放只观察原记录，不再分配消息或调用
- 调用前保存累计预算和完整调用 token；保留原绝对期限，不重置、退款或延长预算
- 成功候选核对当前身份、范围、输入 revision、取消状态、期限、lease 和全部 token 字段，追加实际助手结果及独立完成回执
- 逻辑取消和到期保留未结清的调用 token 与 lease；仅在调用方已观察到本地传输真正结束后，才允许精确 token 的无内容清理
- 写入或 flush 失败使同一 UoW 及行适配器永久不可用；已知唯一冲突保留受控分类，未知错误保留原分类，不自动回滚、重试或重用旧根事务
- SqlWorkUnitOfWork.assert_healthy() 提供明确的自有绑定健康检查，供后续提交边界调用

## 后续集成与限制

Task4b2B 仍需连接提交前后的请求所有者、真实原始响应适配器和有界执行器，并在所有者最终 flush/commit 前调用 UoW 健康检查。自有适配器之外的原始 Session 操作没有被拦截。生产入口继续无条件关闭。

当前完成方法能幂等观察已经提交的相同结果回执，但不能证明未知提交后的重试保留同一个助手消息 UUID 和时间。后续集成必须在第一次完成尝试前保留服务端准备的不可变消息、回执、结果和 token，并通过另行测试和审阅的内部接口重用该确切对象；这不授权重试提供商调用。

本切片未开放 HTTP 对话、提供商派发、修复/重试、重启恢复或实时页面接线。真实 MySQL 唯一性、外键顺序、隔离与回滚、撤权序列化、账号重建安全、选定证据、真实提供商和桌面浏览器仍是独立未完成验收项。现有草稿、学生数据与课程发布安全门保持各自边界。
