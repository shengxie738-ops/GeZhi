# B1 Task5：完整名单预览与确认

已实现 B1 后端名单的合并、替换预览与确认应用，以及独立的预览详情、变更分页接口。本次为源码与合成环境验证检查点，生产教学写入仍由未改动的 `write_safety_unproven` 门禁无条件拒绝。

## 本次能力

- 预览保存完整的目标、新增、保留、更新和退出集合，并计算完整集合的数量与摘要。确认退出必须同时匹配完整摘要和完整数量，不能用界面样本代替
- 请求名单最多 10,000 个标识；最终 `status=active` 的完整名单最多 10,000 条，包含当前生效、未来生效和有效期已结束的记录。已有超限名单可通过明确替换缩减，不会静默截断
- 当前账户、来源教师、可信名单范围及课程内权限共同决定操作权限。无效或超范围目标不会被部分导入；重复输入和规范账户别名的重复项会被识别
- 预览绑定原操作者、课程开设范围、权限版本、相关策略、名单版本及有效期。新确认会重新校验；已接受请求的原回执仅在当前权限仍满足时恢复，不会被当作当前授权凭据
- 退出和重新加入保留同一 Enrollment 标识及关系历史。未指定有效期时，保留记录不被重新开启；明确指定的有效期仅作用于请求目标，并按最终接受时间校验
- 每次已接受应用只生成一份原始回执和一条访问事件。实际受影响的记录更新版本；明确的无变更确认也使名单版本增加一次
- 展示样本和问题样本各最多 10 项。该上限与完整集合、数量、摘要及变更分页独立，并兼顾合法长 Unicode 标识下的 64 KiB 回执限制

## 客户端接入时的计数约定

预览与应用结果的“保留”字段含义不同，不能把预览的所有分类数量直接相加：

- 预览 `keep_count` 包含将更新有效期的保留成员；`update_ids` 是 `keep_ids` 的子集。因此，`target_count = add_count + keep_count`
- 应用结果 `kept_count` 只计入未改变的保留成员，更新成员单独计入 `updated_count`。因此，`target_count = added_count + kept_count + updated_count`
- `kind=keep` 与 `kind=update` 的完整分页遵守同一约定。后续客户端集成文档和对应断言需保留这一语义，不应静默改动已保存预览或原回执
