# B2 Task1：作业与提交的增量数据契约

B2 Task1 已完成限定的源码与合成环境验证，并通过独立审查，未发现阻塞问题。本次建立作业、发布与提交的后端数据契约；实际教学写入仍由未改动的 `write_safety_unproven` 门禁无条件拒绝，B2 尚未激活，也不具备生产上线条件。

## 本次范围

- 新增十个仅允许显式迁移创建的表：作业、作业私有草稿、冻结版本、私有规范、发布预览、发布、发布接收者、提交记录、提交头、评估事件。模块导入与普通启动不会创建这些表，未增加启动或总路由注册
- 作业草稿与冻结版本分开存储，私有规范单独存储。版本按作业与版本号、来源草稿版本保持唯一；每个冻结版本和发布预览最多对应一个发布
- B2 父子关系的组合键与外键绑定相同机构、课程开设及相关作业、版本、发布、学习者。组合外键均声明支持索引，无账户外键或级联删除路径
- 每位发布接收者只对应一个提交头。提交序号唯一约束阻止重复首提交，非空父提交唯一约束阻止分叉；首提交、后续提交及空提交头与版本号的一致性均有数据库 CHECK 声明
- 提供独立的 B2 结构检查与完成账本。B2 结构就绪要求既有 B1 就绪；B1 的契约摘要、表清单和就绪判定保持不变
- 提供使用明确数据库身份的增量迁移计划与应用接口，仅创建缺失且兼容的 B2 表，逐步检查后最后写入 B2 完成账本。不修改、修复或回填 B1；兼容的部分进度允许重入，MySQL 自动提交 DDL 不保证整段迁移回滚。本次未执行实际迁移
- 四项教学开关仍默认关闭。未增加作业操作、权限策略、写入引擎、接口、前端或配置激活

## 数据保护边界

冻结版本、私有规范、发布预览、发布、接收者、提交记录和评估事件的 ORM 实例更新、删除会被拒绝。该保护只作用于实例级 ORM 操作；原生 SQL、Core／批量 SQL 和数据库管理员操作不在该保护范围内。

预览中的角色标识与版本、接收者中的选课标识与版本是历史快照，不连接可变的 B1 角色、选课表，也不授予当前访问权。评估事件的回执外键仅绑定回执标识，另有课程开设范围外键；同一请求、机构、开设、操作者与回执之间的业务绑定仍须由后续 Task2 的封闭写入引擎在同一事务内检查。

可变草稿、提交头的允许修改字段与身份、连续版本推进、父提交序号与当前提交头匹配，以及公开／私有投影和事件元数据限制，仍属于后续引擎与服务实现。JSON 字段当前提供存储契约，尚未形成可操作的发布、提交或评估流程；文本与代码不会在本次范围内执行。
